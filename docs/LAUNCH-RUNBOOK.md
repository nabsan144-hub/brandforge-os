# Canonical launch runbook — BrandForge OS 1.4.1

This replaces the older, conflicting Paddle/setup guides. **Nothing in this branch deploys itself.** Local tests and a health response do not establish revenue readiness. Desktop ownership and Cloud subscriptions are separate; the current policy/pricing drafts assume no pre-existing paid promises.

## 0. Decide and approve before selling

- Review `PRODUCT-ACCEPTANCE.md` and `RIGHTS-MATRIX.md`.
- Approve the proposed Cloud Agency **300/month** cap, daily/concurrency limits, 100 stored brands/account, 10 saved text revisions, 24-month Desktop maintenance scope and the legal/seller/retention details.
- Confirm commercial-appropriate hosting, actual provider prices/quotas, support mailbox and operational staffing. Do not assume a free hosting tier is a production business plan.
- Keep `CLOUD_CHECKOUT_ENABLED=false`, `DESKTOP_CHECKOUT_ENABLED=false`, and the storefront's `desktop_checkout_enabled: false` until the checks below are complete. Never paste service/API/webhook/email secrets into public JavaScript.

## Website demo integration

The final source now includes the MP4, self-contained animated HTML, poster, captions and sample links on the homepage and `/demo`. See `PRODUCT-DEMO.md`. No external media host is required, but verify the actual staging host before publishing. This content does not activate checkout.

## 1. Build and verify the exact source

From a fresh, reviewed checkout, install Node 20+ and Python 3.10+ (CI Linux uses 3.13):

```sh
python -m venv .venv
.venv/bin/pip install -r app/requirements.txt pytest ruff pip-audit
npm ci --prefix cloud
npm ci --prefix sales
npm ci --prefix app/web-modern
.venv/bin/python -m pytest app/tests -q
.venv/bin/ruff check app
npm test --prefix cloud
npm test --prefix sales
npm run build --prefix app/web-modern
node cloud/scripts/sync-schema.mjs --check
python scripts/validate_launch_config.py --prelaunch
```

The incompatible legacy hosted prototype and its deployment recipes have been retired. Required jobs must be green; browser/output/release checks are additional gates, not substitutes. Record the commit and dependency audits, including optional requirements. ChromaDB is intentionally removed from the optional install.

For genuine multi-connection SQL testing, use an **empty disposable PostgreSQL database ending `_test`** with UTF-8 encoding:

```sh
pip install 'psycopg[binary]>=3.2,<4'
BRANDFORGE_TEST_DATABASE_URL=postgresql://.../brandforge_test python scripts/test_postgres_concurrency.py
```

This test creates schemas/tables; NEVER aim it at a production database. PGlite tests also execute fresh/upgrade SQL, role grants, usage, billing/order/revision functions.

## 2. Database migration

1. Back up the target Supabase project and test restoration. Use a staging project first.
2. Apply `supabase/migrations/0001` through `0011` **in order**, using your normal migration runner. Existing installations apply only unapplied migrations. Do not deploy new API callers with old SQL.
3. `cloud/schema.sql` is generated by `node cloud/scripts/sync-schema.mjs`; use it only for a new/manual setup, not as a replacement for migration history.
4. Verify RLS and browser grants on waitlist, keys, generation, checkout, customer binding, billing, orders, adjustments, brands, feedback, revisions and rate/cost tables. Service-role RPC execution must work; anon/authenticated RPC execution must fail.
5. Ledger backfill preserves surviving campaigns **and larger known historical monthly totals**. It cannot reconstruct already-refunded/deleted history. Completed usage is never refunded by deleting content. Account deletion removes per-user usage but not anonymous global cost reservations.
6. Verify the deployed definitions with `pg_get_functiondef`, not only the source file. Ensure the retired `release_campaign_slot` is absent.

## 3. Deploy Cloud (root: `cloud/`), with checkout off

Set server-side variables (use `.env.example` as a checklist, not real secrets):

- `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
- Auth: set Supabase Site URL and allowed confirmation/reset redirects to your actual app origin, including plan/interval query parameters. Verify email confirmation, reset, resend and CAPTCHA/rate settings. Configure the public CAPTCHA site key if using it.
- Providers: `GROQ_API_KEY` and/or `GEMINI_API_KEY`. For each enabled operator provider, set its verified input/output USD-per-million-token rates, e.g. `GROQ_INPUT_USD_PER_MTOK`, `GROQ_OUTPUT_USD_PER_MTOK`.
- `MAX_PROVIDER_DAILY_USD` (default 10), `GENERATION_DAILY_BUDGET` (default 500), `GENERATION_PAUSED=false`. Operator calls reserve a conservative 60,000-token upper bound at the configured maximum rate. This is a safety reservation, not a provider invoice. Failed/uncertain calls do not refund that global reservation.
- Limiter: PostgreSQL by default. If deliberately choosing Upstash, set `RATE_BACKEND=upstash` and both Redis REST variables. There is **no cross-store failover** and no fail-open path.
- Optional personal keys: `BYOK_ENABLED=1` and a 32-byte hex `BRANDFORGE_ENCRYPTION_KEY`. Back it up securely; removing/changing it makes saved keys unavailable rather than silently routing elsewhere.
- `BRANDFORGE_APP_URL`, `BRANDFORGE_MARKETING_URL` as HTTPS origins.
- `CRON_SECRET` (32+ random characters) and a Slack-compatible `OPS_ALERT_WEBHOOK_URL`. The supplied 15-minute Vercel cron requires an appropriate hosting plan. Confirm an actual cron request reaches `/api/maintenance` and alerts arrive.

Use a staging domain and separate sandbox secrets. The API bundles licensed font assets from `api/_assets`; verify they are included in the deployed function. Never expose the local unauthenticated FastAPI app as the Cloud product.

## 4. Paddle Billing catalog and server-only controls

Use **Paddle Billing**, not Classic license/file delivery. The application fulfills Desktop orders itself. The supported USD catalog is:

| Variable | Product | Base price / interval |
|---|---|---|
| `PADDLE_PRICE_PRO` | Cloud Pro | 4900 minor units, month × 1 |
| `PADDLE_PRICE_PRO_YEARLY` | Cloud Pro annual | 49000, year × 1 |
| `PADDLE_PRICE_AGENCY` | Cloud Agency | 9900, month × 1 |
| `PADDLE_PRICE_DESKTOP_OWNER` | Desktop Owner | 19900, one-time |
| `PADDLE_PRICE_DESKTOP_AGENCY_SOURCE` | Desktop Agency + Source | 49900, one-time |

Price IDs must be distinct, active, not placeholders. The server fetches the selected price and rejects wrong amount/currency/interval or an unexpected trial. Review tax/currency localization and discount settings with real sandbox checkouts.

Set `PADDLE_ENV=sandbox`, `PADDLE_API_KEY`, `PADDLE_CLIENT_TOKEN` (`test_…`) and `PADDLE_WEBHOOK_SECRET`. Set a separate 32+ character `BILLING_ACTION_SECRET`. For isolated sandbox tests only, set `BILLING_SANDBOX_TESTING=true` and enable the needed checkout flags. Production uses `PADDLE_ENV=production`, matching live credentials, and an explicit **`BILLING_RELEASE_VERIFIED=true`** after owner sign-off.

Configure signed events to `https://APP/api/paddle-webhook`: transaction.completed; subscription created/activated/updated/canceled/paused/resumed/past_due/trialing as offered in the current dashboard; adjustment.created/updated. Verify raw-body signatures and retries. The adapter preserves UTF-8 bytes. During rotation, an optional `PADDLE_WEBHOOK_SECRET_PREVIOUS` can accept the previous signing key; remove it after the transition.

No browser can choose a raw Cloud price/customer/user entitlement. New checkout is an authenticated server-created transaction with a signed intent. Customer email reuse is not an ownership transfer. Paid plan changes preview and update the **existing** subscription, not another checkout. The portal is generated fresh server-side; do not cache its tokenized URLs.

## 5. Desktop package, private download and email

1. Build the reviewed Owner/Source archives with `app/make_release_zip.py`; inspect their manifests. Owner must not contain `cloud/`, `supabase/`, marketing source, operator runbooks, Svelte development source or CI. Both need the compiled dashboard, fonts, setup/launch scripts and applicable license documents.
2. Extract on a fresh supported machine and follow `START-HERE.md`. Test offline launch **after setup**, native documents, representative presets/custom sizes, client logos, revision/export and installation failure/repair. Windows/macOS testing is a separate release gate.
3. Upload correct ZIPs to a **private** Supabase Storage bucket. Set `DESKTOP_STORAGE_BUCKET`, `DESKTOP_OWNER_PATH`, `DESKTOP_AGENCY_SOURCE_PATH`, and both `DESKTOP_RELEASE_SHA256_*` values from the exact files. Public buckets are rejected before checkout.
4. Set `DESKTOP_DOWNLOAD_SECRET` (32+ random characters), `RESEND_API_KEY`, and verified-domain `DELIVERY_FROM_EMAIL`.
5. A signed transaction.completed event resolves the Paddle customer, stores one durable guest order and queues/sends its download email. It does not need a Cloud account and does not change Cloud entitlement. `delivered_at` means the email API accepted delivery—not proof of inbox arrival.
6. Download links check current order state and nonce before issuing a 60-second private-storage URL. The email link expires after 30 days; `/download-help` provides a rate-limited resend to the original purchase email. A refund cannot erase already-downloaded local files.
7. Migration 0011 freezes each paid order's bucket, path and SHA-256 and adds retry backoff. Existing order rows without that metadata need an operator to reconcile the original artifact; never fill an old order with a new release's checksum. This prelaunch package assumes no existing paid customers.
8. Verify real inbox/spam behavior, duplicate events, failed email, worker restart/lease expiry, missing file, expiry/resend and full/cumulative partial refunds. Pending adjustments do not revoke; approved full/cumulative refunds do. Dispute reversal restores access only if no full refund remains. Adjustment status and totals are defined by Paddle [1](https://developer.paddle.com/webhooks/adjustments/adjustment-updated/).

## 6. Required sandbox lifecycle checklist

Record order/subscription/event IDs privately; do not publish tokens or buyer data.

- Guest Owner and Source purchase → correct private file, receipt, email and checksum.
- Free → Pro; Pro ↔ Agency; Pro monthly ↔ annual; failed payment; stale/tampered preview; no new subscription on paid-to-paid changes.
- Concurrent clicks, closed/reopened checkout, lost creation/save response, delayed/out-of-order/duplicate events. Exactly one intended active subscription.
- `/billing/reconcile` searches uncertain attempts by server-signed intent. An expiry does NOT make an older checkout safe to replace. Unmatched/ambiguous creation stays blocked for support; never clear its DB record just to let a second checkout through.
- Active/past-due/multiple/canceled subscription account deletion; provider outage; ambiguous cancellation; auth deletion failure. Identity/data remain until cancellation is confirmed. Immediate cancellation is clearly confirmed; it is not a refund.
- Desktop-only, Cloud-only and both-product buyers; purchasing, canceling or refunding one product must not overwrite unrelated rights.
- Portal invoice/payment/cancellation navigation; annual renewal terms; completed usage carried across plan changes.
- Local test traffic load, provider/rate outages, daily caps, spend alert, latency alert, failed-event and email retry alert.

For production, repeat an **owner-authorized actual purchase and refund** and record the result privately. Do not infer this from a sandbox or HTTP 200.

## 7. Operate and recover

Monitor `/api/maintenance` summaries and the private `paddle_events`, `desktop_orders`, `payment_adjustments`, `checkout_intents`, `billing_subscriptions` and `billing_customers` tables. Retryable events use leases; delivery uses a durable claim/outbox. An uncertain transaction must be reconciled with Paddle before unlocking another checkout. Review unresolved cart/price mismatches manually; do not grant access from an unverified client email or user_id.

On incident: set `GENERATION_PAUSED=true` and/or disable the appropriate checkout flag. Keep portal/cancellation/export available. Do not roll back to the old campaign-deletion refund logic. Database rollback requires a backup/migration plan; dropping ledgers/commerce records is not a safe rollback.

A successful source test suite is **local implementation evidence**, not legal approval, a host quota guarantee, real-provider quality validation or a claim of perfection.

## Repeat the browser regression suite locally

The Cloud tests in this script use **explicit synthetic auth/API fixtures**, not a real signed-in account. Static marketing pages use the actual files.

1. Install Python Playwright and Chromium (`pip install playwright`; `python -m playwright install chromium`), plus the npm dependencies above.
2. Serve the static site locally: `python scripts/serve_sales_preview.py --port 8765`.
3. In another terminal: `python scripts/browser_regressions.py`. It fails on page errors, horizontal overflow or the selected axe violations and saves `qa-results/` locally (git-ignored).
4. Optionally start a separate Desktop test process on port 8767 with a fresh `BRANDFORGE_DATA_DIR`, then set `BRANDFORGE_DESKTOP_QA=1` when running the script. Do not use a customer data directory for screenshots.
5. These Chromium checks do not replace manual keyboard/screen-reader, Firefox/WebKit, real auth/provider/payment, Windows/macOS or native Word checks.

Full refunds and cancellation are separate operations: stop renewal through the portal when ending Cloud service; issuing a refund alone is not an instruction to silently cancel a different active subscription. Review paid access against the intended provider state. Keep signing keys backed up; rotating download/action secrets invalidates outstanding signed links/intents unless deliberately migrated.

On small development machines, run `python scripts/check_release_quality.py` sequentially. It uses automatically cleaned disk-backed scratch space, avoiding repeated raster/PDF tests filling a RAM-backed `/tmp`. Do not run the full database, browser and build jobs concurrently on a 2 GB machine.
